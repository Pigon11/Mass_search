# Лабораторная работа: "Mass search"
## Селезнев Е.А.
## Группа: 6133-010402D

### Что делал:
Решал задачу массового поиска подстрок - когда у нас есть большой буфер данных (просто последовательность байт) и множество подстрок разной длины, и нужно выяснить, какие из этих подстрок встречаются в буфере. 
Сначала написал эталонный алгоритм на CPU, потом сделал параллельную версию на GPU, а затем реализовали матричный метод, который описан в методическом пособии.

## CPU
Берём буфер и подстроки, организуем три вложенных цикла - по подстрокам, по позициям в буфере и по символам подстроки. Если все символы совпали - подстрока найдена.
<img width="474" height="497" alt="image" src="https://github.com/user-attachments/assets/164c1944-2940-4839-b4c9-a376ec221eea" />

С буфером 100 КБ и 2000 подстрок он занял 752 миллисекунды.

## Простой GPU
Распараллелен именно поиск разных подстрок. CPU перебирал их последовательно, а теперь 2000 потоков на GPU делают это одновременно. При этом внутри каждого потока остаётся цикл по буферу - его никто не отменял, но теперь таких циклов выполняется много параллельно.

<img width="683" height="439" alt="image" src="https://github.com/user-attachments/assets/cf41cf93-03e6-4611-8a11-2b4485bad659" />


На практике этот метод дал 17-кратное ускорение (43 мс вместо 752 мс).


## Матричный метод GPU
Из 3 раздела. Тут нужно создать матрицу размером |подстроки| * |буфер| и инициализировать её длинами подстрок. Потом делаем один проход по буферу, и для каждого символа уменьшаем соответствующие ячейки матрицы. В конце там, где остался ноль - подстрока найдена.

Распараллелено теперь не подстроки, а каждый символ буфера обрабатывается отдельным потоком. То есть если буфер содержит 100 000 байт, запускается 100 000 потоков. Каждый поток берёт свой символ, смотрит, в каких подстроках он встречается, и атомарно уменьшает нужные ячейки матрицы.
<img width="707" height="422" alt="image" src="https://github.com/user-attachments/assets/474d9663-7ca4-4560-9315-cf0e4765d278" />

Делается всего один проход по буферу, а не N проходов, как в первых двух методах. Вместо того чтобы для каждой подстроки сканировать весь буфер, один раз проходим по буферу и обновляем информацию сразу для всех подстрок.
Матричный метод отработал за 10.3 миллисекунды, что в 73 раза быстрее CPU и в 4 раза быстрее простого GPU метода.
